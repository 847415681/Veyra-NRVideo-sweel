## 1. 功能

一个美颜节点有两个独立子功能，各自开关：

- **人脸原画保护**：在识别到的人脸内把本帧原画（任何效果之前的画面：调色、超分、各层 NR、更早的美颜节点都没作用过）
  混回来：`P = lerp(C, O, 强度 × 人脸遮罩)`，遮罩为 1 处直接取原画像素（逐位相同）。范围可选整张脸 / 仅皮肤；
  区域扩展 −10%…30%、边缘羽化 0…20%（相对人脸大小）。
- **磨皮**：在 P 上做 SkinSoft 式的肤色选择、细节保护与纹理保留，平滑本身换成快速导向滤波（GPUPixel 的方差自适应思路），
  另有整体强度、磨皮程度、半径（1080p 像素，随画面缩放，0…12）、细节保护、纹理保留、提亮，范围仅人脸 / 全部肤色，
  高级项为肤色范围（色相中心/范围、饱和度与亮度上下限、边界柔和）。两项共用人脸置信度门限和遮罩显示（导出时自动关闭）。

人脸识别由同一条链上的所有美颜节点共用（档位 性能 320 px·10 Hz / 均衡 512 px·15 Hz / 精细 640 px·30 Hz、最多人脸 1…8、
跟踪平滑 0…1），随链保存、导出时冻结。只有节点开关和实例数会重建处理图，其余全部是实时 uniform。

列表模式：画质页“美颜”卡（NR 组与保护之后、RTX Video HDR 之前），最多 6 层，层卡可复制、上下移动、恢复默认、删除，
组开关记住各层原状态；新层默认关闭（加层不改变画面），四个预设（自然磨皮 / 轻度磨皮 / 人脸原画保护 / 保护 + 自然磨皮）
一键打开。节点模式：目录项“美颜”，最多 6 个，编辑器与列表共用 `qml/Veyra/BeautyEditor.qml`。

## 2. 结构

| 部分 | 文件 |
|---|---|
| 设置、校验、预设编码 | `include/veyra/engine/BeautySettings.h`；`EnhancementSettings`、`EffectChain`（`toChain`/`fromChain`/节点顺序）、`GraphDescription`、`ExportFeaturePolicy` |
| 存储 | 预设库 v15、链会话 v10，写入独立的 `.beauty` 文件，旧文件逐字节不变；导出协议 11 |
| 人脸检测 | `src/beauty/OnnxLite.cpp`（只读解析 ONNX 权重）、`src/beauty/YuNetGpu.cpp` + `shaders/BeautyYuNet*.hlsl`（YuNet 全网络手写 D3D12 compute） |
| 跟踪 | `src/beauty/FaceTracker.cpp` + `shaders/BeautyTrack.hlsl`：GPU 上 NMS（与 OpenCV FaceDetectorYN 相同的整像素框规则）、α-β 滤波、稳定 id、丢失后宽限再淡出；画面路径不回读，只每槽读回 64 字节计数头给界面 |
| 节点 | `src/pipeline/BeautyPass.cpp` + `shaders/Beauty{Roi,Stats,Blur,Apply}.hlsl`、`Beauty.hlsli`、`BeautyFaces.hlsli` |
| 图 | `EnhanceGraph`：E0 插入槽（源尺寸 SourcePost、PreSr、PreNr、链尾 Tail），`bindSlotPassInput` 同时修正 NR 旁路时只重绑调色的问题 |
| 界面 | `QmlPlayerBridge` beauty*、`ProPage`、`NodePage`、`BeautyEditor.qml`，计时行“人脸识别”“美颜…美颜 6”（有样本才显示），84 条四语言翻译 |

执行：ROI pass 用一个线程算出本帧所有人脸外接圆的并集（全部肤色时为整帧），写 `ExecuteIndirect` 参数；输出先
`CopyResource(input)`，所以区域外逐位等于输入；磨皮在约 540 行的统计网格上做均值/方差（4 次可分离高斯），最后一个全分辨率
pass 合成。颜色：平滑在感知域（sRGB 曲线，白点以上对数延续，保留负值分量）进行，所有混合回线性；HDR 以 203 nit 为白。

原画来源在建图时确定：没有融合调色 → 直接用 `srcRgba_`（零成本）；只有附加调色 → `preGradeRgba_`；有融合调色 →
`beautyOriginal_`，只在保护开启的帧多做一次未调色转换 + 拷贝。

## 3. P0 结论与偏差

1. **推理路线**：用手写 HLSL 跑 YuNet（约 5.3 万权重、45 层），不引入 ONNX Runtime / DirectML / WinML 新二进制
   （AGENTS 规则下新增运行库需逐项授权）；与 OpenCV 5.0.0 FaceDetectorYN 在 8 张图 × 3 个尺寸、两个模型版本上结果一致
   （修正 NMS 为 OpenCV 的 `Rect2i` 截断后 30/31 张人脸的差异消失）。因此没有做 WinML / ORT 实测对照。
2. **磨皮算法**：SkinSoft 的稀疏 9 点模糊在大半径下有重影，改为快速导向滤波（He & Sun 2015）；默认值按实测调整：
   lena 皮肤方差 0.002–0.007、眼部 0.016–0.029，得出 ε = 0.012 − 0.010 × 细节保护；夜间游戏画面皮肤亮度 0.03–0.17，
   亮度下限 0.04、饱和度下限 0.08（SkinSoft 原为 0.12 / 0.18，会丢掉暗处的脸）。
3. **复审第 7 条（检测会话挂在引擎会话上）**：未照做。跟踪器随处理图创建，重建时重新解析模型并上传权重，实测约 40 ms
   （GUI 日志 `[beauty] instance=` → `face tracker ready`），只在节点开关/实例数变化时发生，实时参数不重建。
4. **复审第 9 条**（保护基准）保持方案语义：原画为本帧任何效果之前的画面，4K 输出时脸部回到放大前的源画面。
5. **未实现**：单节点“本节点前后对照”；暂停调参时没有美颜输入缓存（会重跑 NR）；大图分块处理跳过美颜并在状态栏提示。

## 4. 实测（RTX 5070，本机，一次运行）

| 项 | 结果 |
|---|---|
| 关闭子功能的节点 = 无节点 | 逐位相同 |
| 全强度保护（调色之下） | 脸部核心 = 未调色原画、远处 = 调色结果，均逐位相同 |
| 50% 保护 | 最大差 1 级（剪切像素除外） |
| 两个节点（先磨皮再保护） | 脸部核心回到原画 |
| HDR（P010 PQ） | 检查块逐位不变，负值分量保留，峰值 12.547 |
| 跟踪（48 帧、每帧平移 3 px） | 12 次检测，最大中心误差 9.8 px / 脸宽 146 px，复位立即检测 |
| 磨皮（强档，原尺寸图） | 皮肤细纹理 −24.3% / 眼部 −5%（lena）、−16.1 / −7.6（astronaut）、−10.7 / −8.3（messi）、−21.3 / −13.1（夜间游戏 gta-f040） |
| 无模型 | 预览照常（提示“人脸模型文件缺失”），导出拒绝开始 |

## 5. 顺带修复

- **导出协议**：美颜提交把写端改为 11，但 worker 仍只认 10，导致本分支所有导出都会被拒（`ExportWorkflowTests beauty`
  发现）；改为两端共用 `Shared::kVersion`。
- **节点模式未改动的节点**：关闭且为默认值的抗锯齿 / 美颜节点在设置里没有实例（`toChain` 不写，保持旧预设格式），
  节点顺序还原时因此拒绝整条链——新加的美颜节点（默认关闭）和关掉的默认抗锯齿节点都会触发；`restoreRuntimeOrder`
  现在把它还原为同样的未改动节点（`EffectChainTests` 新增 4 项）。抗锯齿分支本身仍有此问题。
- 抗锯齿编辑器“强度”的繁中 / 日文翻译缺失。

## 6. 没有验证

- AMD / Intel 显卡；真实采集卡与真实游戏画面的肉眼评价（只用了公开测试图和 4 帧 GTA 截图）；长时间运行与显存曲线；
  2 / 6 节点下的耗时；CPU 渲染线程增量（预算 P95 ≤0.3 ms，未单独测）；融合调色时额外转换的耗时。
- 打包脚本尚未把模型放到 `runtime/models`（运行时也查找 `runtime_local/models` 和程序目录下的 `models`），发布前要补。
- 撤销 / 重做对美颜参数的覆盖未单独测试。
